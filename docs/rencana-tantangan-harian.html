Angka-angka ini diambil dari dump produksi, bukan perkiraan. Dua di antaranya mengubah rancangan: 535 soal berskor menentukan berapa lama tantangan harian bisa berjalan sebelum mengulang, dan hanya satu hasil Tes IQ PRO di seluruh database menentukan bahwa papan Top 50 PRO akan berisi satu nama saat diluncurkan.

Temuan yang menentukan arsitektur

Celah yang harus ditutup lebih dulu

SyncController::syncData menerima score dan total_questions mentah dari client tanpa satu pun validasi. Hari ini dampaknya kecil — user hanya bisa mengotori riwayatnya sendiri. Begitu ada papan peringkat publik, siapa pun bisa mengirim {"score": 9999, "total_questions": 1} dan menguasai Top 100 dalam hitungan hari.

smarttesiq BACKEND/app/Http/Controllers/SyncController.php:35–42

Konsekuensinya satu, dan ia menentukan seluruh bentuk fitur: tantangan harian harus dinilai di server, bukan di aplikasi. Kunci jawaban tidak boleh ikut terkirim ke HP.

Terpisah, tapi ada di file yang sama

Kredit memakai max($user->kredit_iq_pro, $request->kredit_iq_pro) tanpa validasi. Satu permintaan HTTP buatan bisa memberi kredit PRO tak terbatas — pembelian dalam aplikasi bisa dilewati sepenuhnya sekarang juga. Bukan bagian dari fitur ini, tapi berada di file yang akan kita sentuh.

Validasi hanya bisa menolak angka yang mustahil, bukan angka yang masuk akal tapi palsu. Solusi penuhnya adalah memindahkan semua tes ke penilaian server — proyek terpisah yang jauh lebih besar. Untuk sekarang: beri lencana terverifikasi hanya pada papan harian, dan tampilkan jumlah peserta di setiap papan.

Keputusan yang sudah dikunci

  • Komposisi soal harian: 5 soal — 4 gratis + 1 PRO. Soal PRO berfungsi sebagai corong penjualan: di layar hasil diberi label asalnya, lalu tombol beli. Satu per hari terlalu sedikit untuk menggantikan pembelian, cukup untuk membuat penasaran.
  • Soal habis → diulang / diacak. Tidak ada generator. Pemilihan mengutamakan soal yang paling lama tidak dipakai; kalau semua sudah terpakai, acak ulang dari awal.
  • Set soal bersifat global. Semua user mengerjakan 5 soal yang sama tiap hari — syarat mutlak agar peringkat harian adil.
  • Iklan: satu untuk membuka, satu untuk melihat hasil, dengan jalan keluar wajib saat iklan tidak tersedia.
  • Bug PRO-mencemari-IQ-Reguler: diperbaiki. Karena hanya ada ~2 hasil PRO di produksi, dampaknya praktis nol sekarang — dan kalau ditunda akan jadi permanen.
  • Nama tampilan wajib opt-in. users.name berisi nama lengkap asli dari akun Google dan tidak boleh dipakai di papan peringkat.

Urutan deploy — tidak boleh dibalik

Kunci agar aplikasi live tidak rusak: semuanya bersifat menambah, tidak ada yang mengubah. Client 2.2.1 yang sedang berjalan tidak tahu-menahu soal tabel dan endpoint baru, jadi ia tidak bisa rusak karenanya.

01
Migration — hanya CREATE TABLE & ADD COLUMN nullable Tidak ada ALTER pada kolom lama, tidak ada DROP. Aman dijalankan sementara kode lama masih melayani permintaan, karena kode lama tidak menyentuh tabel baru.
02
Kode backend — controller & route baru Butuh tabel dari langkah 1 sudah ada. Kalau dibalik, endpoint baru menabrak tabel yang belum lahir dan mengembalikan 500.
03
Rilis APK ke Play Store Terakhir. Rollout Play Store bertahap, jadi selama beberapa hari client lama dan baru berjalan bersamaan — backend harus sudah siap melayani keduanya sebelum APK pertama sampai ke user.

Nama tampilan

Privasi

Migration baru: users.display_name (nullable, unique). Dialog minta nickname saat pertama membuka papan peringkat. User yang tidak mengisi tidak masuk papan — opt-in, mati secara default.

Kenapa opt-in wajib

User 2.2.1 sudah login di bawah kebijakan privasi yang tidak pernah menyebut nama mereka akan ditampilkan ke user lain. kebijakan-privasi.html dan form Data Safety di Play Console perlu diperbarui sebelum papan peringkat aktif.

Tabel percobaan & aturan peringkat 
CREATE TABLE daily_attempts (
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id        BIGINT UNSIGNED NOT NULL,
  challenge_date DATE NOT NULL,
  started_at     TIMESTAMP NOT NULL,
  submitted_at   TIMESTAMP NULL,
  correct        TINYINT NULL,
  duration_ms    INT NULL,
  iq_harian      SMALLINT NULL,
  UNIQUE KEY uniq_user_day (user_id, challenge_date),
  INDEX rank_idx (challenge_date, correct DESC, duration_ms ASC),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

UNIQUE (user_id, challenge_date) menutup celah mengulang tantangan, dan tanggalnya dari server sehingga mengubah jam HP tidak berpengaruh.

Penentu seri wajib ada

Rumus 70 + (pct × 70) dengan 5 soal hanya menghasilkan enam nilai: 70, 84, 98, 112, 126, 140. Kalau peringkat hanya berdasar skor, ratusan orang seri. Urutannya wajib correct DESC, duration_ms ASC — sekaligus membuat tantangan terasa kompetitif.

Alur iklan

Layar pembuka  →  [Tonton iklan & mulai]  [Nanti saja]
                        ↓ reward earned
                  POST /daily/start → 5 soal
                        ↓ selesai
                  POST /daily/submit   ← skor SUDAH tersimpan
                        ↓
Layar hasil    →  [Tonton iklan & lihat hasil]  [Lewati]

Urutan ini penting: submit dulu, iklan belakangan. Kalau iklan diputar sebelum submit dan user menutup aplikasi, jawabannya hilang padahal sudah dikerjakan.

Dua masalah di RewardedAdManager

Kalau iklan belum termuat, ia hanya menampilkan snackbar lalu return — user di jaringan lemot terkunci total dari fitur. Dan tidak ada callback saat user menutup iklan sebelum selesai, jadi pemanggil tidak tahu harus mengaktifkan lagi tombolnya.

Fase 2 & 3 — Tiga papan peringkat

Top 20 Harian

Tanpa mekanisme reset
SELECT u.display_name, a.correct, a.duration_ms, a.iq_harian
FROM daily_attempts a JOIN users u ON u.id = a.user_id
WHERE a.challenge_date = CURDATE()
  AND u.display_name IS NOT NULL
  AND a.submitted_at IS NOT NULL
ORDER BY a.correct DESC, a.duration_ms ASC
LIMIT 20;

Selalu sertakan peringkat user sendiri di bawah daftar walaupun ia di urutan 300. Tanpa itu, hampir semua user melihat papan yang tidak ada dirinya dan langsung kehilangan minat.

Top 100 IQ Reguler

Ada bug yang ikut diperbaiki

Backend menghitung ulang IQ komposit dari test_results yang sudah tersinkron, meniru rumus di final_result_screen.dart:75–86: ambil hasil terbaru per test_name, saring nama yang mengandung Verbal / Deret / Logis / Spasial / Klasifikasi, jumlahkan, lalu 70 + round(pct × 70).

Bug-nya

contains('Deret') juga cocok dengan 'Deret Angka (PRO)', dan contains('Verbal') cocok dengan 'Analogi Verbal (PRO)'. Rumus yang berjalan sekarang diam-diam mencampur hasil PRO ke dalam skor "IQ Reguler" — artinya user yang membeli PRO ikut mengubah skor Reguler-nya, dan pemeringkatan jadi tidak setara.

Keputusan: dikecualikan di kedua sisi dalam satu rilis. Hanya ~2 hasil PRO yang ada di produksi, jadi hampir tidak ada user yang skornya berubah.

Jangan hitung saat diminta

Menghitung komposit seluruh user tiap kali papan dibuka akan berat begitu user bertambah. Simpan hasilnya, perbarui setiap kali /sync dipanggil user tersebut, lalu tambahkan cache Laravel 5 menit di atasnya.

Kalau bootstrap/cache/routes-v7.php ada, routes/api.php yang baru akan diabaikan sampai cache dibangun ulang. Cek ini lebih dulu — artisan route:cache termasuk perintah tulis dan butuh persetujuan.

Yang masih menunggu

  • Isi smarttesiq BACKEND/.env.example belum diperiksa. File itu sudah ikut ter-push. Aturan proyek memblokir pembacaan berkas .env*, jadi perlu kamu yang memastikan tidak ada kredensial asli di dalamnya.

  • Key Gemini lama. APK 2.2.1 yang beredar masih membawa .env di dalamnya. Setelah rilis baru turun, key lama sebaiknya dicabut.
